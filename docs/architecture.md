# 一期架构与验收边界

## 最小链路

```text
用户选题、受众、要求与现行资料
  -> 需求明确后按需调用只读素材 MCP，获得历史图文参考候选
  -> 展示候选证据，人工逐项保留/排除
  -> 3—5 页制作单（读者文字与画布制作要求分开）
  -> 本机词库预检拟上图文字，处理命中
  -> 人在无限画布自由生成、修改、选图
  -> 回传最终图，Agent 读图与必要的顺序澄清
  -> 标题、正文、标签校准，同一词库复核实际成图与终稿，人工确认
  -> 本机版本化 output/
```

客户端负责对话、模型推理、图片读取及其已具备的 MCP 工具。项目源码只负责共享格式、持久状态、校验和归档，不启动第二套 Agent 平台。状态文件按任务放在本机被 Git 忽略的目录；一条任务只接受一份明确确认过的参考清单，后续增删来源须重新确认。参考候选与保留清单分开存储，制作单引用 ID 必须属于保留清单。

分享包自带只读 Teedy MCP 代码、独立安装器和素材库技能，供下载者用自己的 Teedy 账号配置。它不包含 Teedy 数据、标签树、内部别名、远端地址或任何凭据。工作台技能与素材库技能分别安装；MCP 使用远端既有素材库，不新建第二套仓库。

## 来源合同

候选历史文档至少显示 Teedy 文档 ID、标题、摘要、预览入口、`zip_url` 或附件下载入口、拟借鉴点及事实口径风险。用户上传资料记录本地文件名和来源说明。候选的检索排名不代表适用性；未入选的文档不得作为内容证据。全数排除后允许继续使用用户要求和已提供的现行内部资料，由 Agent 原创视觉与信息结构；这不自动授权 Web 搜索，也不允许把模型记忆当事实依据。用户另行明确要求公共资料研究时，才使用可追溯的外部来源并逐项标注。

## 母版裁剪

- 保留并改造拆解、逐页初稿、中文润色的 Skill 与结构化 schema，移除热点笔记和品牌角色作为硬前提。
- 保留状态持久化、人工编辑/确认与版本化归档的实现思路；改为单任务模型并使磁盘 manifest 与审核状态同步。
- `agent-runner.mjs` 原本直接启动 `codex exec`，还耦合热点、OpenCLI、角色生图、渲染和发布。只迁移可用的校验与失败处理逻辑，不把它原样带入双客户端链路。
- 一期不带热点研究、自动选题、内容账号、故事线、发布、ROI、网页和桌面壳。画布直连作为后续实测增强。

## 双端验收

用户已在 WorkBuddy 实测旧版素材 MCP 检索、人工保留/排除候选及三页制作单通过项目校验；本轮需求门槛、图文过滤、Canvas 节点制作单和两阶段词库扫描已有本地实现与离线测试。开发侧尚需复核加载、权限和分段耗时。分别在 Codex 与 WorkBuddy 完成新版画布成品回传、读图校准、审核、交付包及中断续做的整轮实机验收；一端成功不代表另一端通过。
