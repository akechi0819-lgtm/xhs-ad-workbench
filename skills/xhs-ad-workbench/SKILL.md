# 小红书投放素材生产工作台

先阅读本项目 `AGENTS.md`、`README.md` 与 `docs/usage.md`，然后使用项目中 `scripts/workbench.mjs` 和 `content/` 的结构约束推进当前任务。每个对话线程只关联一个本机任务文件；续做时先读取保存状态，不凭模型记忆重建。

1. 默认做小红书**图文**。先把业务范围、具体问题、目标人群、内容目标和现行依据整理成需求卡；模板只帮助表达，不要求机械填满。能写出明确的图文检索问题就推进，缺关键信息才追问，不自行猜定用户未说清的范围或问题。已有完整需求只复述一次。
2. 需求明确、确需历史参考且员工素材 MCP 可用时，直接调用只读素材工具，不要求用户再写命令或触发词。宽泛需求先澄清。检索结果按关联性和覆盖面筛选展示；少量相关结果全部展示，结果较多时由模型选择高相关候选，数量只作软建议，不静默放宽范围条件。
3. 将所有拟用历史文档先展示给用户：标题、Teedy 文档 ID、摘要、预览与下载入口、拟借鉴点、可能过时的事实。等待用户明确保留或排除每一项，并将选择写入任务。未确认的候选不能进入制作单。全部排除后，若视觉或事实依据仍不足，提示用户可补充现行品牌/课程资料或外部参考图（包括竞品素材）；资料已足够时直接按用户需求继续。Agent 可原创画面与信息结构，竞品参考只借鉴版式与信息组织，不复制原文、Logo 或独特画面。不要自行把 Web 搜索、模型记忆或笼统“公开信息”当事实来源。只有用户明确要求公共资料研究时，才另行查可追溯来源。没有依据的具体政策、数字和服务承诺不写进成品。
4. 以保留项、用户上传的参考和已核实的现行资料制作 3—5 页图文方案。每套共用品牌要求；每页只提供一份精确图上文案、画风、布局、按需 Logo/参考图来源。保存后由项目导出器自动组合出按顺序可复制的标题、正文、画风与最终指令节点及全部连线。精确文字与已提供的公司 Logo 原件要进入生成输入，目标是直接出可用海报或只需小幅修图；不要默认改成无字背景加后期人工排字。送画布前用随包词库预检图上文字，命中项由人修改或说明保留依据，改制作单后重新扫描。不能用历史笔记替代现行资料。
5. 用户在现有无限画布自行生成和修改后，**用客户端实际打开并放大查看每张最终图片**，不得凭文件名、制作单或 Agent 记忆写审核结论。逐图给用户一份简短的可操作审核：可见文字逐字记录及错漏、标题与信息层级/手机端易读性、Logo 与品牌一致性、图片和原定主题是否对应；问题必须指明第几张、画面位置及如何修改。若客户端无法读图，明确说明无法审核，不得填空文字并宣称通过。顺序不清时才询问。按实际图重新校准标题、正文、标签与 CTA，再用同一份本机词库扫描图中文字及发布文案；命中词由人决定修改或说明保留依据，不自动套用原 HTML 的替换或合规结论。
6. 回图后先给用户上述逐图问题和配套发布文案；需要修改时保持任务可换图、可改文案，用户发回新图就重新读图和复审。只有用户认可当前图文后，才运行 `submit` 生成待审素材包，再由用户明确确认后运行 `approve`。不要把制作单初稿说成发布终稿，也不要把本地词项扫描说成已经完成视觉审核。

每次交接只说完成了什么和**唯一下一步**：确认需求 → 筛选参考 → 审画布制作单 → 审终稿。用业务语言，不把内部状态码交给使用者。

不自动发布，不操作投放平台，不生成 ROI 看板，不把密钥或内部素材提交到 Git。
